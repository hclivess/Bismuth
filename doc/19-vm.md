# doc/19 — Decentralized-apps VM (smart contracts)

The on-chain, **post-fork** smart-contract layer. This is the complete map of what exists, what is
tested, and what is still missing — so nothing is assumed done that isn't.

Everything here is **inert until hf2 activates** and behind the `vm` config flag (default **off**; on for
regnet tests). It adds **no behaviour to the current chain**.

## How it fits together

```
vm: transaction (consensus-ordered, signed, in a block)
        │  digest, ONLY when block_height >= node.fork_height  (digest.py)
        ▼
vm_engine.apply_block_rows ──> per tx: parse vm:deploy / vm:call ; value custody deposit/withdraw
        │
        ▼
   bismuth_riscv.py   the single execution engine: deterministic RV32I RISC-V interpreter
        │             (ALU / branches / load-store / JAL(R) / LUI / AUIPC, gas-metered, ECALL host ABI)
        │  reads/writes
        ▼
   vm_state.py  (LMDB: code + storage + custody balances)  ──>  state_root()  ──> node.vm_state_root
```

Why RISC-V and not a bespoke bytecode: it's a real, frozen, widely-implemented ISA with mature C/Rust
toolchains, inherently deterministic in its base integer set — the direction Ethereum itself is taking
("RISC-V over the EVM"). One engine, no dispatch.

## Value custody — how it works (DONE)

Contracts move real BIS, and a reorg can't corrupt it. The obvious approach (contract balance = its ledger
balance) is **not rollback-deterministic**: on a reorg the state is rebuilt by re-executing the `vm:` txs,
but a contract's *historical* spendable balance can't be reproduced from the rolled-back ledger, so a
TRANSFER that succeeded originally would fail on replay and diverge the root. The fix — implemented — holds
the contract balance **in `vm_state`** (committed to the state root), not the ledger:
  - **Deposit:** a `vm:call` sent to `VM_SINK` (a keyless 56-hex address) debits the sender's ledger to the
    sink and credits the called contract's `vm_state` balance. The sink's ledger balance mirrors the sum of
    all contract balances (double-entry) → the BIS supply stays exact.
  - **Withdraw:** a TRANSFER inside the contract debits its `vm_state` balance; the digester settles a
    `vm_payout` — a negative-height ledger row FROM the sink TO the recipient (the reward-mirror pattern).
  - **Replay:** re-executing the `vm:` txs rebuilds the `vm_state` balances exactly (deposits add, transfers
    subtract), so `self_balance` is reproducible at every height → the rollback rebuild matches, and the
    state root (which now covers balances) confirms it.

Tested end-to-end on regnet (`test_vm_value.py`): BIS funded through custody is released to a fresh address
that receives it; and after a withdraw is REORGed away, the custody balance and the state root return to
their exact pre-withdraw values — the determinism property, asserted.

## Layer model (important)

Execution is **main-layer** (every full node runs it; `vm:` txs are consensus-ordered and final), and the
state root is now **consensus-ENFORCED**: post-fork the miner commits the pre-state root in the coinbase
(after the hf2 signal, PoW-hashed like the rest of the nonce) and the digester **rejects** a block whose
committed root disagrees with its own — *or omits it entirely* (the root is mandatory post-fork, so a
miner can't dodge the check by leaving it out). On mainnet the coinbase is built by the (external) miner,
so upgraded miners read the current root from `/api/vm/contracts` and embed it, exactly like the hf2
signal; the regnet block generator does this automatically. So a non-determinism bug is a **caught
block-rejection, not a silent divergence** — main-layer execution *plus* the hash-anchored integrity an L2 hash-commit gives,
with no separate layer or sequencer. See doc/17 for the trade-off.

## Next steps (in order)
Every consensus-critical piece is wired and tested. What remains is **optimisation / DX, not an upgrade
blocker**:
1. **Merkle trie** — incremental root + inclusion proofs for light clients (the flat root works today).
2. **Full gas metering** — per-op gas priced against fees + a fee market (a flat `vm:` surcharge prices
   calls today).
3. **Compiler toolchain** — C/Rust → RISC-V packaging (raw RV32I deploys today).
